**Exit criteria**:

### Step 3: Block dangerous URL schemes in normalizeWebsite

**Refs**: M5 (Medium)
**Files**: `src/lib/place-review-utils.ts`

**Context**: `normalizeWebsite()` at line 10-22 prepends `https://` if no protocol is present, but does not reject `javascript:`, `data:`, or `vbscript:` schemes. If `place.website` is `javascript:alert(1)`, it passes through unchanged. This is rendered as `<a href={place.website}>` in the place detail page (`src/app/mekan/[slug]/page.tsx:241`).

**Tasks**:
1. After trimming in `normalizeWebsite()`, check if the value matches a dangerous scheme regex: `/^(javascript|data|vbscript):/i`
2. If it matches, return `null` (strip the dangerous URL entirely)
3. Only prepend `https://` if the value does NOT already start with `http://` or `https://`

**Exit criteria**:
- `normalizeWebsite('javascript:alert(1)')` returns `null`
- `normalizeWebsite('data:text/html,<h1>hi</h1>')` returns `null`
- `normalizeWebsite('https://example.com')` returns `'https://example.com'` (unchanged)
- `normalizeWebsite('example.com')` returns `'https://example.com'` (unchanged behavior)

### Step 5: Install jose + create session management module

**Refs**: C1, H2, C4 (Critical/High)
**New dependency**: `jose` (JWT library — lightweight, zero-dependency, edge-compatible)
**Files**: NEW `src/lib/admin-session.ts`

**Context**: Admin auth currently sends the raw password in an `X-Admin-Password` header on every request. The password is stored in `localStorage`, readable by any XSS. We need to replace this with short-lived JWT sessions stored in httpOnly cookies.

**Tasks**:
1. `npm install jose`
2. Create `src/lib/admin-session.ts` with:

   - `verifySessionToken(token: string): Promise<{ valid: boolean; expired: boolean }>` — verifies JWT signature and expiration

   - `clearSessionCookie(response: NextResponse): void` — sets cookie with MaxAge=0
   - `getSessionTokenFromCookie(request: Request): string | null` — reads the session cookie
   - `isSessionAuthenticated(request: Request): Promise<boolean>` — reads cookie, verifies JWT, returns true/false

**Exit criteria**:
- `src/lib/admin-session.ts` exports all listed functions
- JWT uses HS256 with a key derived from env vars
- No password is ever stored in the JWT payload

### Step 6: Create in-memory rate limiter

**Refs**: C2, C4 (Critical)
**Files**: NEW `src/lib/rate-limit.ts`

**Context**: No rate limiting exists on any endpoint. The public submission endpoint (`POST /api/places/submit`) and admin session endpoint (`POST /api/admin/session`) are both brute-forceable.

**Tasks**:
1. Create `src/lib/rate-limit.ts` with:
   ```
   type RateLimitEntry = { count: number; resetAt: number }
   ```
   - `rateLimitStore`: In-memory `Map<string, RateLimitEntry>` (module-scoped)
   - `checkRateLimit(key: string, maxRequests: number, windowMs: number): { allowed: boolean; remaining: number; resetAt: number }`
     - If no entry or expired: create new entry with count=1
     - If entry exists and not expired: increment count
     - Return `{ allowed: count <= maxRequests, remaining: max(0, maxRequests - count), resetAt }`
   - `getRateLimitKeyFromRequest(request: Request): string` — extracts IP from `x-forwarded-for` header (first IP) or `x-real-ip` or falls back to `'unknown'`
   - Periodic cleanup: expose `cleanupRateLimitStore()` that removes expired entries (called from a timer or lazily)
2. Export `checkRateLimit` and `getRateLimitKeyFromRequest`

**Exit criteria**:
- Rate limiter is purely in-memory (no Redis needed)
- Sliding window per key with configurable max requests and window
- Key is IP-based from standard proxy headers
